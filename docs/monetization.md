## 前提（プロダクトの位置づけ）

| レイヤー | 役割 | 課金 |
|---------|------|------|
| **ダッシュボード** | 複数ソースの生トレンドを一覧（JP/US） | **無料**（集客・信頼の入口） |
| **AIサマリー** | 順位の動き・カテゴリ横断・一行結論など **解釈** | **有料候補** |
| **X 20時投稿** | 急上昇3件のティーザー | 無料（導線） |

- 原稿の正本: [`docs/summaries/`](summaries/README.md)（現状 **サイト未公開**）
- 品質・配信SLAの検証: [`summary_pattern_a_phase1.md`](summary_pattern_a_phase1.md)（パターンA・フェーズ1）
- トップ画面の導線: `templates/partials/ai_summary_fake_door.html`（Fake door・Preview）
- 関心登録 API: `POST /api/waitlist/ai-summary`（`ai_summary_waitlist` テーブル）
- 休眠中のメール基盤: `ENABLE_SUBSCRIPTION_UI` + `services/subscription/`

**売るもの:** 「20ソースを自分で追う時間」を、**毎朝決まった時刻に届く読み物**として提供する。

### マネタイズ案（5パターン）

実装コストと検証速度のバランスで選ぶ。**推奨は A → 必要なら B で並行検証**。

| ID | 案 | 概要 | 向いている段階 | 単価イメージ |
|----|-----|------|----------------|-------------|
| **A** | **フリーミアム + メール配信** | トップに一行結論（無料）→ 全文はメール／会員 | 本命・中長期 | 月 ¥500〜980（日次） / ¥1,500〜2,000（日次+週次） |
| **B** | **note / Substack 有料** | 外部プラットフォームで課金、トップは CTA のみ | **最速で「払う人」検証** | 月 ¥500〜 / 記事 ¥300〜 |
| **C** | **B2B ブリーフィング** | 編集部・広報・スタートアップ向け Slack/PDF | 単価重視・少数顧客 | 月 ¥9,800〜 |
| **D** | **寄付 / Buy Me a Coffee** | 支援者に週次先行などソフト特典 | 本格課金の前段 | 任意 |
| **E** | **タイムボックス商品（パターンAそのまま）** | 「毎日10:30」「月曜11:00」の約束を SKU 化 | A/B とセット | A/B の約束時刻をそのまま商品説明に |

## 推奨ロードマップ（全体像）

フェーズ1（原稿品質・欠配・リンク）が出口条件を満たしたあと、次の順で進める。

```
フェーズ1  原稿生成・レビュー・パターンA運用（課金なし）
    ↓
フェーズ2a  トップに実データ Top1 + Waitlist（まだ課金なし）
    ↓
フェーズ2b  限定有料（note または メール月額・10〜30人）
    ↓
フェーズ3   サイト内サマリーページ + 本番配信自動化
```

### フェーズ1 → 2 へのゲート

[`summary_pattern_a_phase1.md`](summary_pattern_a_phase1.md) より:

- [ ] **4週連続で欠配ゼロ**（または短縮テンプレで必ず配信）
- [ ] 日次遅延が許容内（週の過半数が目標+15分以内）
- [ ] リンク事故が週あたり許容未満
- [ ] 主観品質が継続的に「出したい」水準（例: 平均 3.5/5 以上）

### トップ画面からの導線（共通）

JP `/`・US `/us` のダッシュボード上部 3 カラム:

```
[ このページで分かること ]  [ AIサマリー ]  [ データ鮮度 ]
```

**やること（フェーズ2a以降）**

1. `status: approved` の最新日次から **「今日の一行結論」** を Fake door に表示
2. 「Top5を見る」→ Waitlist または有料ページへ
3. GA4: `fake_door_view` / `ai_summary_top5_click` → 登録率を週次で記録

**やらないこと**

- トップに Markdown 全文をベタ置き（重くなる・stateless 哲学とズレる）
- ダッシュボード本体の有料化（入口を潰す）
- 無制限の履歴アーカイブ公開（スコープを決めてから）

## ステップバイステップ手順

各ステップの **完了条件** を満たしたら、上の [進捗チェックリスト](#進捗チェックリスト) を更新する。

### 共通：フェーズ1（原稿・品質・SLA）— 課金前

**目的:** 毎日・毎週、信頼できる原稿を **欠配なく** 出せる状態にする。  
**参照:** [`summary_pattern_a_phase1.md`](summary_pattern_a_phase1.md)

#### Step 1-1 — 日次原稿の自動生成を安定させる

1. GitHub Actions `ai-daily-summary.yml` が **JST 06:50 前後** に動いていることを確認する。
2. 失敗時に `docs/summaries/daily/YYYY-MM-DD.generation.json` がコミットされることを確認する。
3. 手元で再生成が必要なとき:
   ```bash
   python scripts/generate_ai_daily_summary.py --write --force --business-day YYYY-MM-DD
   ```
4. **完了条件:** 直近7日分で、意図しない欠配がない（生成失敗は JSON で理由が追える）。

#### Step 1-2 — 週次原稿の自動生成を安定させる

1. GitHub Actions `ai-weekly-summary.yml` が **月曜 07:30 JST 前後** に動いていることを確認する。
2. 対象週の日次ファイル（月〜日・最大7本）が揃っていることを確認する。
3. 出力先: `docs/summaries/weekly/YYYY-Www.md`（週次 + ホット同梱）。
4. **完了条件:** 直近2週分の週次ファイルが存在し、日次の羅列ではなく「流れ」がある。

#### Step 1-3 — レビューゲート（draft → approved）を回す

1. 毎朝、当日配信対象の `docs/summaries/daily/{business_day}.md` を開く。
2. [`summary_pattern_a_phase1.md`](summary_pattern_a_phase1.md) の **毎日チェックリスト** を実施:
   - 一行結論がソースと矛盾していない
   - 各論点に最低1リンク
   - 憶測・未確認の明示
3. 問題なければフロントマターを更新:
   ```yaml
   status: approved
   reviewer: "名前"
   reviewed_at: "2026-06-11 10:00 JST"
   ```
4. **完了条件:** 配信に使う日は **approved のみ** という運用が合意されている。

#### Step 1-4 — SLA・品質を記録する

1. スプレッドシートまたは [週次メモ](#週次メモ) に記録: `date`, `type`, `target_time`, `actual_time`, `delay_min`, `missed`, `link_issues`, `quality_1-5`
2. 週末に **主観品質の平均** を見る（5=明日も読みたい、1=出したくない）。
3. **完了条件:** 4週分の記録が溜まり、[フェーズ1 → 2 へのゲート](#フェーズ1--2-へのゲート) を評価できる。

#### Step 1-5 — X との役割分担を固定する

1. **20時 JST:** X は急上昇3件のみ（[`daily_guide.md`](x_post_samples/daily_guide.md)）。
2. **翌朝:** AI日次サマリーが読み物本体。
3. X 文案に「詳細は朝のサマリー／ダッシュ」と書くかどうかを決める（フェーズ2aでCTAと揃える）。
4. **完了条件:** 「夜=X、朝=サマリー」がブレない。

### 案 A：フリーミアム + メール配信（本命）

**商品:** 無料=一行結論 / 有料=日次全文 +（オプション）週次バンドル  
**約束時刻:** 日次 10:30 JST / 週次 月曜 11:00 JST

#### Phase 2a — トップ接続 + Waitlist（課金なし）

##### Step A-2a-1 — approved 原稿から「一行結論」を取り出す

1. 入力: `docs/summaries/daily/{最新 business_day}.md` で `status: approved`。
2. 抽出箇所: `## 今日の一行結論` セクション。
3. JP/US で同じ観測日にするか、JP のみ先行するかを決める。
4. **完了条件:** サンプル1日分で一行結論が機械的に取れる。

##### Step A-2a-2 — Fake door に実データを表示する

1. 対象: `templates/partials/ai_summary_fake_door.html` / `app.py` の `AI_SUMMARY_FAKE_DOOR`。
2. 「準備中」固定を **最新 approved の一行結論** に差し替える。
3. 原稿がない・draft のみの日はフォールバック（例:「本日のサマリー準備中」）。
4. **完了条件:** 本番 `/` で一行結論が表示される。

##### Step A-2a-3 — Waitlist フォームをモーダルに載せる

1. API: `POST /api/waitlist/ai-summary`（`email`, `region`, `source`）。
2. モーダルにメール入力 + 送信 + 成功/エラー表示。
3. `source` に `fake_door_modal` などを付与。
4. **完了条件:** 本番で DB `ai_summary_waitlist` に登録される。

##### Step A-2a-4 — 計測とコピーを整える

1. GA4（既存）: `fake_door_view`, `ai_summary_top5_click`。
2. 追加検討: `waitlist_submit`, `waitlist_success`。
3. モーダル文案: 提供予定（時刻・価格帯は未定でも可）を1〜2文。
4. **完了条件:** 1週間分の view / click / 登録数が取れる。

##### Step A-2a-5 — 2〜4週間の関心検証

1. 週次で Waitlist 増分・CTR を [週次メモ](#週次メモ) に記録。
2. [合格ライン](#合格ライン) を満たすか判断。
3. **完了条件:** 合格、または B 案並行の判断。

#### Phase 2b — 限定有料（10〜30人）

##### Step A-2b-1 — SKU と価格を決める

1. **Daily:** 毎朝10:30 JST・日次全文メール
2. **Weekly bundle:** 月曜11:00 JST・週次+ホット同梱
3. 価格帯（仮）: Daily ¥500〜980/月、Bundle ¥1,500〜2,000/月
4. 返金・休刊・スケジューラ遅延時の前提を1段落で書く。
5. **完了条件:** Waitlist 向け案内文に載せられる。

##### Step A-2b-2 — 配信手段を選ぶ

**ルート1: SubscriptionManager を復活**

1. `ENABLE_SUBSCRIPTION_UI=true` の影響範囲を確認。
2. 配信内容を AIサマリー Markdown（HTML化）に差し替え。
3. [`email_setup_guide.md`](email_setup_guide.md) を確認。

**ルート2: Stripe Payment Link + 手動メール**

1. Waitlist 上位に Stripe リンクを送る。
2. 支払い確認後、メーリングリストに追加。
3. 週次で原稿をコピペ配信（自動化は Phase 3）。

4. **完了条件:** 初回課金者1人に SLA 内で全文が届いた。

##### Step A-2b-3 — Waitlist から限定招待

1. 案内メール: 提供内容・価格・開始日・unsubscribe。
2. 先着 N 名 or 抽選 — ルールを決めて実行。
3. **完了条件:** 有料会員 ≥10人（または N）で1週間配信。

##### Step A-2b-4 — 継続率と品質フィードバック

1. 解約・返信を記録。
2. 品質 1〜5 を週平均で継続。
3. **完了条件:** churn 許容内、重大な事実誤りゼロ。

#### Phase 3 — サイト内ページ + 配信自動化

##### Step A-3-1 — サマリー閲覧ページ（軽量）

1. ルート案: `/summary/daily/YYYY-MM-DD`, `/summary/latest`（要認証 or トークン）。
2. `status: approved` のみ表示。
3. **完了条件:** 有料会員が URL で当日分を読める。

##### Step A-3-2 — 配信自動化

1. approved コミット → 10:30 JST 配信ジョブ。
2. 失敗時: Discord 通知。
3. **完了条件:** 7日連続・手動なし配信。

##### Step A-3-3 — 週次バンドル同梱

1. 月曜 11:00 JST に `weekly/YYYY-Www.md` を配信。
2. **完了条件:** Bundle 会員に週次+ホットが届く。

### 案 B：note / Substack 有料（最速検証）

**目的:** サイト内決済を後回しにし、**払う意愿** だけ先に測る。

#### Step B-1 — 媒体を1つに絞る

1. note **または** Substack のどちらか一方。
2. **完了条件:** 有料シリーズの空箱が作れる。

#### Step B-2 — 無料 / 有料の境界を決める

1. 無料: 一行結論 + 論点1つ（または先頭300字）。
2. 有料: 全文（論点、動いた3つ、カテゴリ別、複数ソース重なり）。
3. **完了条件:** [`2026-06-10.md`](summaries/daily/2026-06-10.md) 級の原稿で切れる。

#### Step B-3 — 初回5本を手動投稿

1. `approved` 原稿を note 用に整形。
2. 週5本 × 1週間。
3. **完了条件:** 5本公開、有料設定 ON。

#### Step B-4 — トップ Fake door から note へ CTA

1. ボタン例:「今日の全文を読む（note）」。
2. UTM: `?utm_source=trend-dashboard&utm_medium=fake_door`
3. **完了条件:** GA / note の PV が取れる。

#### Step B-5 — 転換判断

1. 4週で有料会員数・売上を記録。
2. 足りなければ価格・導線を調整。足りれば案 A Phase 3 へ。

2. **完了条件:** PDF or Notion 1ページ。

#### Step C-2 — サンプル配信（無償・2週）

#### Step C-3 — 契約・請求

2. **完了条件:** 有料契約1件。
