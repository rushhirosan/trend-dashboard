# 有料サマリー検証：パターンA・フェーズ1

トレンドダッシュボード由来のデータを前提に、**日次サマリー／週次サマリー／週のホットトピック**を継続生成し、**品質・更新リズム・リンク健全性**を観察するためのテンプレートとチェックリスト。

本番スケジューラは **JST 1 / 7 / 13 / 19** に一括取得が走る（完了までバラつく）。サマリーの「確定時刻」は **取得開始ではなく、キャッシュが実用上揃った後** を想定する。

### リポジトリへの保存（サイト非公開）

完成した原稿は `**docs/summaries/`** に Markdown でコミットする（日次・週次のファイル名や週次とホットのまとめ方は `[summaries/README.md](summaries/README.md)`）。**アプリのページではまだ読み込まない。**

配信前に品質を確認する場合は、原稿のフロントマターで `status: draft` → レビュー後 `approved` とし、**承認済みのみ配信に使う**（運用の詳細は `summaries/README.md`）。

## パターンA（タイムボックス）


| 出力            | ユーザー向け約束（案）                                | 備考                     |
| ------------- | ------------------------------------------ | ---------------------- |
| **日次サマリー**    | 毎日 **10:30 JST**（遅延時は **11:30 JST まで**）    | 朝の更新（7時台ジョブ）完了後に生成する前提 |
| **週次サマリー**    | 毎週 **月曜 11:00 JST**（遅延時は **12:00 JST まで**） | 「先週」の境界を固定する（下記）       |
| **週のホットトピック** | **週次と同じタイミング**で同梱                          | フェーズ1では運用を一本化          |


### 先週の定義（フェーズ1で固定）

- **推奨**: 先週 = **月曜 0:00 JST 〜 日曜 23:59 JST**
- 変更する場合はフェーズ1の最初に決め、途中で変えない（版を上げる）

---

## フェーズ1の目的（3〜4週）

- **課金・公開は必須にしない**（内部／極小限定でも可）
- 同じ骨格で **毎日・毎週** 生成し、次を記録する  
  - 目標時刻からの**遅延**  
  - **欠配**（出せなかった日／週）  
  - **リンク**の切れ・取り違え  
  - **主観品質**（読みたさ 1〜5 でも可）

### フェーズ1の出口条件（例）

次を満たしたらフェーズ2（限定公開など）を検討する。

- **4週連続で欠配ゼロ**（または欠配時も「短縮テンプレ」で必ず配信できた）
- 日次の遅延が目標に対し許容内（例：週の過半数が **目標+15分以内**）
- リンク事故が **週あたり許容未満**（または即修正できる運用が回っている）

## コピペ用テンプレ — 日次サマリー（パターンA）

```markdown
# 日次サマリー — YYYY-MM-DD（JST）

- **対象**: （例：前日〜当日朝のダッシュボード更新反映を前提とした観測）
- **生成・送信完了**: HH:MM JST（目標 10:30、上限 11:30）

## 今日の一行結論

（2〜3文。断定はソースがある範囲に限定）

## 論点（3〜5）

### 1. （見出し）

- **なにが起きているか**（2〜4文）
- **ソース**: [タイトル](URL) · [タイトル](URL)
- **注意**: 憶測・未確認なら明示（例：「公式発表は未確認」）

### 2. （見出し）

（同様）

### 3. （見出し）

（同様）

## データ前提メモ（任意）

- スケジューラ遅延・特定ソース欠損があれば1〜2行
```

## コピペ用テンプレ — 週次サマリー（パターンA）

```markdown
# 週次サマリー — 週番号 / YYYY-MM-DD〜YYYY-MM-DD（先週・JST）

- **対象週**: 月0:00〜日23:59（定義はフェーズ1で固定）
- **生成・送信完了**: HH:MM JST（目標 月曜 11:00、上限 12:00）

## 今週の流れ（短文）

（5〜8文。単なる日次の繰り返しにしない）

## 来週に残る論点（2〜4）

- （論点）— 1〜2文
- …

## ソース一覧（週を通じた根拠リンク）

- [タイトル](URL)
- …
```

## コピペ用テンプレ — 週のホットトピック（パターンA）

件数上限を決める（例：**5〜7**）。フェーズ1では超えない。

```markdown
# 週のホットトピック — 同上の週

選定基準（フェーズ1で固定・列挙だけでもよい）:

- 複数ソースで伸びた / 議論が続いた / 日本側への波及が見える など

## 1. （トピック短名）

- **なぜホットか**（2〜4文）
- **ソース**: [タイトル](URL) · …

## 2. …

（上限まで）
```

## チェックリスト — 毎日（日次）

- 当日の一括取得が **実用上参照可能**（欠損ソースがあればメモ）
- **一行結論**がソースと矛盾していない
- 各論点に **最低1リンク**（可能なら2〜3）
- 憶測・未確認を **明示**した
- **10:30 目標 / 11:30 上限** に収めた（遅れたら理由を記録）
- 記録シートに **遅延分・欠損・トラブル** を1行追記

---

## チェックリスト — 毎週月曜（週次 + ホット）

- **先週の境界**がテンプレと一致
- 週次が **日次のコピペの羅列**になっていない（「流れ」がある）
- ホットトピックが **件数上限**内
- 各ホットに **ソース**がある
- **11:00 目標 / 12:00 上限** に収めた（遅れたら理由を記録）
- 記録シートに **週次ブロック**を追記

---

## 記録シート（スプレッドシート等）の最低列案


| date | type (daily/weekly) | target_time | actual_time | delay_min | missed (Y/N) | link_issues | notes |
| ---- | ------------------- | ----------- | ----------- | --------- | ------------ | ----------- | ----- |


週次・ホット同時送出の場合は `type` を `weekly_bundle` などにして1行でもよい。

## 品質メモ（任意・30秒）

毎回、主観でよいので 1〜5：

- 5 = 明日も読みたい
- 1 = 出したくない

週末に平均を見る。
